# Kiruk Studio — documentation overview

> **Purpose of this folder:** explain the _concept_ and _how we will develop it_.
> The workbook is a **spark**. This is not the finished brand, not the visual system, and not a plan for how the brand “lasts.”
>
> Filed 2026-09-02 from founder overview. Markdown on purpose: light, shareable, iterable.

## Purpose

Document the thinking that lets kiruk **happen**: one designer, one client, experimental work. Capture process and ideas. Do not freeze identity, look, or feel here.

## Scope of the workbook

The printed _17 Day Brand_ book (and kiruk’s fill of it) is an **exploratory framework**.

| It is                        | It is not                                  |
| ---------------------------- | ------------------------------------------ |
| _How_ we will create a brand | _What_ the brand looks like                |
| Process and sparks           | Finished product                           |
| Fuel for later pitch         | Visual style guide                         |

## Documentation format

All of this layer is **Markdown**. No slide deck required. Easy to share, easy to rewrite.

## Orchestrator and workflow

Arun orchestrates. Agent files.

1. **Idea generation** — spark in the workbook (and this folder).
2. **Project definition** — client brief (or self-brief), chosen theme, experimental approach.
3. **Design and development** — iterate, assets, prototypes.
4. **Review and feedback** — client (or public) review, fold it in.
5. **Delivery** — finish, then **write the outcome back** into the workbook / this KB.

Detail: [workflow.md](./workflow.md). Capture protocol: [method.md](./method.md).
