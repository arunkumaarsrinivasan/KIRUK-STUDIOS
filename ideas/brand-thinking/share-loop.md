# Share loop — how process stays public and reusable

Inspiration named by the founder: **x.com** (how creators share and iterate), plus writing on **experimental studios** and **open-source creative workflows**.

This file is steal-the-thinking, not a content calendar and not a clone of those tools.

## From X (process in public)

Patterns worth keeping for kiruk (aligned with existing build-in-public: process open, money closed):

- Show **stages**, not only the hero shot: spark → rough → choice → break → fold-in → done.
- Narrate **judgment** (why this move), not a tutorial dump.
- Treat the audience like collaborators: ship, hear, change, **say what changed**. Small loops.
- Process threads attract the curious; they do not replace the one-to-one client room.

Reject: hustle cadence as identity, posting revenue, turning kiruk into a growth account.

**Hangouts (People 06):** Instagram, blogs, sometimes Substack. Not TikTok. LinkedIn is not the main room for this person.

Studio already has a boundary for this (`openspec/specs/build-in-public`). Story drops stay the only public revenue surface.

## From experimental / OSS creative practice (2025–26 notes)

Not prescriptions. Signals:

- **Diverge, then converge.** Exploration is a revisable intent, not a prompt to a single pretty frame (IdeaBlocks / DIS-style research: reuse _how_ you explored — block, path, project — not only the final look).
- **Canvas / notebook as source of truth.** Work and agents (or collaborators) share one inspectable state — same spirit as scribble-first, not “chat until a logo appears.”
- **Open the tools, not the client’s guts.** OSS products (planned) can be forkable; client universes and fees stay closed.
- **Human in the loop.** One designer reviews; tools do not replace the one-to-one.

References to return to (not endorsements): process-on-X guides that stress sketch-to-final; open creative workspaces (e.g. node/canvas OSS) as _proof people want inspectable process_; academic work on divergent intent vs one-shot generation.
