# Brand thinking capture

The user is the **orchestrator**. Treat each dump as a **document-creation task**.

Read [ideas/brand-thinking/method.md](ideas/brand-thinking/method.md) first, then [ideas/brand-thinking/docs-map.md](ideas/brand-thinking/docs-map.md) if the dump could belong to more than one layer. Then [ideas/brand-thinking/README.md](ideas/brand-thinking/README.md).

## Do

1. Write the dump into the matching file (`overview.md`, `themes.md`, `projects.md`, `workflow.md`, or `ideas/brand-thinking/chapters/NN-*.md`).
2. Route meaning into topic files. Split topics; do not grow one blob.
3. Add seeds to `ideas/brand-thinking/ideas.md`. Add moves to `ideas/brand-thinking/task.md`.
4. If it fights the live repo, update `ideas/brand-thinking/tensions.md`. Do **not** edit `VISION-MISSION.md`, manifesto, or `openspec/specs/` unless asked to **lock**.
5. Do **not** spawn `kiruk-ism/` or product registry entries from a dump.
6. Reflect back in kiruk language (short). Wait for correction.
7. Run `/kiruk-capture` after a substantive dump.

## Do not

- Copy the purchased workbook (no substantial verbatim).
- Clone Boring Studio’s OS or templates.
- Put fees, runway numbers, or secrets in git.
- Rebuild the whole studio from one chapter.
- Skip ahead until the founder dumps the next chapter.

## After each dump checklist

Copy from method.md: chapter → topics → ideas → tasks → tensions → README status → capture → reflection.
