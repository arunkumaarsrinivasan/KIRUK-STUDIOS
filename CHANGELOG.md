- **`kiruk-portal` onboarding — phase 1: the eye that reads you (intro screen).** First step toward an eye-as-only-asset, emotion-by-color onboarding. Emotion is **revealed-preference, not self-report** — derived from pointer velocity (arousal), never asked: still→`focus`(ink), slow→`calm`(cyan), wandering→`curiosity`(lime), fast/driven→`anticipation`(orange). Sketch roughness via SVG turbulence/displacement; idle drift + blink keep it alive; respects `prefers-reduced-motion`. `tsc` clean; `/onboard` serves 200.

Sequence: intro(✓) → client(self-reference) → personality(keep drag-compass, tokens→eyes) → vibe(eye dilation, settle-latency) → scribble(eye absorbs energy) → **product(rebuild — weakest: promotion/prevention regulatory-focus + sentence-completion projective, replacing 5 open textareas)** → summary(composite eye = emotional fingerprint, peak-end).

Following explore-now/spec-after: build the eye to see it first, formalize after.

## How to write an entry

1. New change? Add under `## [Unreleased]` → one of `Added` / `Changed` / `Removed` / `Fixed` / `Decisions`.
2. Each bullet: what changed + **Why**: line explaining intent.
3. On release (brand v1, phase completion, etc.): rename `Unreleased` → `[vX.Y] — YYYY-MM-DD`, start a fresh `[Unreleased]` on top.
4. Plan shifts (roadmap edits, scope drops) MUST land here, not in the roadmap diff alone.
